# 勾股OA 6.1.2 测试项目（公开版）

对一个开源 OA 系统（ThinkPHP 8 + MySQL）的**权限、审批流、合同、薪资** 4 个模块做接口自动化、
性能测试与 UI 取证。项目重点不是“跑通页面”，而是把访问控制类问题用**可复现的断言**固定下来。

> 被测系统是第三方开源项目 **勾股OA 6.1.2** 的本地部署实例。本仓库只包含我编写的测试代码、
> 用例与脱敏后的结论，**不包含被测系统源码**，也不代表该产品的官方质量结论。

## 环境要求

- WSL2 Ubuntu，已部署勾股OA 6.1.2；
- Nginx + PHP 8.2-fpm + MySQL 正常运行；
- Python 3.10+（开发时用 3.13）；
- JMeter 5.6.3（只有性能测试需要）；
- Playwright Chromium（只有 UI 取证需要）。

被测系统需保留演示数据中的出厂账号（`admin`、`fengcailing`、`yucixin` 等）。
pytest 套件还依赖 `testmin(108)` / `testemp(109)` 与角色组 4 作为**环境前置对象**，
首次运行用 `setup_test_account.py` 创建；请不要把它们当成测试垃圾清掉。

## 快速开始

```bash
# 1. 安装依赖
python -m pip install -r requirements.txt
python -m playwright install chromium      # 仅 UI 取证需要

# 2. 配置（.env 已被 .gitignore 忽略）
cp .env.example .env                       # PowerShell: Copy-Item .env.example .env
# 编辑 .env：至少填 OA_HOME / OA_ADMIN_PWD / OA_USER_PWD

# 3. 首次运行：创建最小权限账号与角色组 4
python 03_接口测试/setup_test_account.py

# 4. 跑全套接口自动化
cd 03_接口测试/接口自动化
python -m pytest
```

其他常用命令：

```bash
python -m pytest -m qx          # 只跑权限体系
python -m pytest -m sp          # 只跑审批流
python -m pytest -m ht          # 只跑合同
python -m pytest -m xz          # 只跑薪资
python -m pytest --allure-brief # Allure 只附失败证据
```

Allure 报告建议设置 `ALLURE_NO_ANALYTICS=true` 后再 `allure serve`，
否则报告页可能因外部统计请求而长时间卡住。

## 关键设计

1. **按响应体 `code` 判定，不看 HTTP 状态码。**
   该系统的权限拦截返回 HTTP 200 + `code=405`；只看状态码会把“被拦截”读成“正常”。
   `code=1` 是通用业务错误（含“请先登录”），HTTP 500 则说明请求已越过鉴权闸门。
2. **已知缺陷用 `xfail(strict=True)` 固定。**
   缺陷修复后用例 XPASS 会直接判失败，提醒回来销账；它不是永不失效的注释。
3. **夹具自包含。**
   会话级 fixture 负责搭建与回收，跑完回读核对：本套件创建的业务数据自动回收；
   `testmin(108)` / `testemp(109)` 与角色组 4 是**环境前置对象**，按设计保留，不属于回收范围。
   加 `--keep-fixtures` 可停在中间态排查。
4. **UI 对照法。**
   疑似接口越权，只有在“界面拒绝同一用户、接口却放行”时才确认，降低误报。
5. **性能只看趋势，不设绝对阈值。**
   WSL2 单机部署下绝对 TPS 没有迁移性；本次瓶颈定位为 PHP-FPM
   `pm.max_children=5`，属于部署配置而非产品缺陷。
