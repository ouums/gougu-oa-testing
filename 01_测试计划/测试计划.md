### 范围说明
- **不覆盖**：客户管理、项目管理、财务管理、知识网盘、移动端、企业微信/钉钉集成等模块（受 4 天工期限制，且与本项目差异化定位无关）
- 系统共 12 个一级模块、507 个权限节点；本次聚焦上述 4 个模块
- **薪资管理的范围边界**：本产品**没有算薪引擎、没有个税计算公式** —— `deduct_tax` 等扣款项均为**手工录入**（`records_add` 只对空值置 0，无任何运算）。故本例**只测「汇总求和是否正确」，不测「个税算得对不对」**（后者在本产品中无独立权威可校验）。详见 §1.1

| 外勤 | **已覆盖**：「外出」即 `oa_outs`（假勤四模块之一），已由审批流模块用例覆盖 |

> **已知支持**：多级审批（`check_step_sort` + `flow_list`）、会签/或签（`check_types`：1=会签全过、2=或签任一）、抄送（`is_copy`）、退回（`is_back`）、撤回（`check_status=4`）。

| 类型 | 手段 | 说明 |

| UI 取证 | Playwright | **仅做登录 + 逐页截图 + 缺陷复现取证**，不写完整回归脚本 |
| 数据校验 | SQL 脚本 | 核对业务操作后落库一致性（审批状态回写、合同状态字段） |

### 2.1 专项方法：UI 对照法（防误报）
任何"接口可越权访问"的判定，**必须先在界面上验证**：若界面同样对该用户开放，则属设计如此，不报缺陷；若界面受限而接口不受限，则为确凿缺陷。

### 2.2 兼容性说明
本次**仅在 Chrome 最新版**测试，不覆盖 Firefox / Edge / Safari 及移动端浏览器。

### 3.1 登录自动化方案（已解决）
系统登录强制图形验证码。经源码分析：`config/captcha.php` 设 `math=true`，验证码为算术题 `x(10~30) + y(1~9)`，**答案恒为 11~39 的整数**；`Captcha::check()` 以 `password_verify` 比对明文。本地部署下读取 PHP session 文件 + 穷举 11~39 即可还原。
已封装 `03_接口测试/oa_login.py`，实测通过。
> ⚠️ 该方案依赖本地文件系统读取，**仅适用于本地测试环境**，不适用于线上系统。

## 7. 准出条件

- 用例执行率 **≥ 95%**，且**未执行的用例须逐条书面说明原因**（记「待执行」三态之一，不得为凑数记成「通过」或「失败」）
- **P0 / P1 缺陷全部记录并反馈**，附复现步骤 + 截图 + 接口证据；受限于本系统为第三方开源产品、测试方无代码修改权，P0/P1 缺陷的闭环方式为**「修复验证」或「风险知会」二选一**——已书面知会并留档即视为该项达标
- P2 缺陷记录率 ≥ 80%
- 交付物（计划 / 用例 / 缺陷 / 报告）**数字口径完全一致**（用例数、执行数、通过数、缺陷数）
- 缺陷可复现、结论可讲解

### 7.1 缺陷分级标准

| 等级 | 定义 | 示例 | 处理要求 |
|---|---|---|---|
| **致命 P0** | 系统崩溃、数据丢失/泄露、核心功能完全不可用 | 水平越权查看他人合同、审批后数据丢失、登录后白屏 | 必须修复，否则不可发布 |
| **严重 P1** | 核心功能异常但有绕过方式、状态流转错误、权限控制失效 | 审批状态不更新、合同无法归档、低权限用户可删除单据 | 必须修复 |

### 水平越权重点验证目标
`Leaves` / `Overtimes` / `Trips` / `Outs` 四个控制器的 `view()` / `add()`（编辑分支）/ `del()` **均无单据归属校验**，且这四个控制器位于 `BaseController::$not_check` 白名单中（不走 RBAC）。

**关键反证**：审批撤回接口 `app/api/controller/Check.php:598` **有**归属校验（`$detail['admin_id'] != $this->uid` → 拒绝），说明开发者具备归属校验意识，但未一致地应用到单据接口——**该不一致性显著提高水平越权缺陷的可信度**。
